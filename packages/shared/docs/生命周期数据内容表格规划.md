# 生命周期数据内容表格规划

## 1. 生命周期同步结果

正式模块通过生命周期主列表接口获取“已发布到站点”数据，不再依赖页面 DOM 表格。

```text
POST /api/kiana/mms/robin/searchForSemiSupplier
secondarySelectStatusList = [12]
```

## 2. SPU 表

一行一个店铺级 SPU。同步完成后，该表同时作为自动建档和图片关联的来源快照。

| 字段 | 说明 |
| --- | --- |
| SPU | Temu SPU 标识 |
| 商品 ID | Temu 商品 ID |
| 商品货号 | 主商品原始货号，如接口提供；原始响应不截断 |
| SPU 主图 URL | 生命周期主列表主图 URL；流量主图优先写入产品基础表 |
| 最低供应价 | 商品列表中的“核价价”；SKU 优先读取 `siteSupplierPriceList[].supplierPriceValue`，按分转元后取所有有效 SKU 的最低值 |
| 限流价格 | “日常申报价调整为”和“按活动申报价报名活动”等明确调价候选的最低值；对应 `suggestActivitySupplierPrice` / `targetSupplyPrice`，按分转元，不使用供应价兜底 |
| 最近同步批次 | 当前数据来源批次 |

## 3. SKC 表

一行一个 SPU 下的 SKC。

| 字段 | 说明 |
| --- | --- |
| SPU | 所属 SPU |
| SKC ID | SKC 标识 |
| SKC 完整货号 | 生命周期返回的原始货号，用于内部绑定和详情追溯 |
| SKC 展示货号 | 完整货号清理空白后取前两个 `-` 分段，优先用于产品管理匹配 |
| SKC 属性 | 颜色、款式等属性，保存原始属性 JSON |
| 最低供应价 | SKC 下有效 SKU 核价价最低值；兼容 SKC 自身供应价字段 |
| 限流价格 | SKC 下属 SKU 的 `suggestActivitySupplierPrice` / `targetSupplyPrice` 等调价候选最低值；没有时为空 |

SKC 的业务属性范围为颜色、款式等子商品属性；未知属性不丢弃，保留原始 JSON。

## 4. SKU 表

一行一个 SKC 下的 SKU。

| 字段 | 说明 |
| --- | --- |
| SPU | 所属 SPU |
| SKC ID | 所属 SKC |
| SKU ID | SKU 标识 |
| SKU 完整货号 | 生命周期返回的原始货号，用于内部绑定和详情追溯 |
| SKU 展示货号 | 完整货号清理空白后取前两个 `-` 分段，SKC 无匹配时作为兜底 |
| 尺码 | 尺码字段，如接口提供 |
| SKU 属性 | 尺码、规格等属性，保存原始属性 JSON |
| 最低供应价 | 商品列表中的核价价，读取 `siteSupplierPriceList[].supplierPriceValue`，例如 `7201` 表示 `72.01 元` |
| 限流价格 | 读取 `siteSupplierPriceList[].suggestActivitySupplierPrice` 和 `targetSupplyPrice`；分别表示日常调价/活动目标价候选，例如 `4100` 表示 `41.00 元`、`373` 表示 `3.73 元`，多个候选取最小值 |

SKU 的业务属性范围为尺码、规格等具体 SKU 属性；未知属性不丢弃。

## 5. 产品管理关联表

产品管理记录不复制生命周期明细，而是在查询时通过当前店铺和货号计算关联结果。生命周期批次完成后，缺失的产品管理主档会由默认 `admin` 账号自动创建，并标记来源为 `lifecycle`。

自动建档计算：

1. 自动建档货号取生命周期货号前两个 `-` 分段，例如 `DY-189-green` 转为 `DY-189`。
2. 货值从第一段末尾数字解析，例如 `Z38-Y22` 的货值为 `38`。
3. 序列号从第一个 `-` 后、第二个 `-` 前的分段提取数字，例如 `Z38-Y22` 为 `22`、`HB28-GY59` 为 `59`。
4. 旧内部产品 ID 数据库列仅保留兼容，不再作为产品管理页面展示字段。
5. 默认重量为 `0.3 KG`。
6. 总成本、推荐售价和利率门槛值由现有定价函数根据货值和当前设置实时计算。
7. 最低供应价只作为生命周期采购成本分析值，不能替代产品管理货值。
8. 使用 `source_type = manual | lifecycle` 区分手工与生命周期来源；自动同步不得覆盖手工主档。
9. 本轮不回填或修正历史产品主档货号，只保证后续生命周期自动建档应用正确截断规则。

匹配顺序：

1. 比较货号时去除空白并转大写。
2. 生命周期 SKC/SKU 货号取前两个 `-` 分段作为比较键。
3. 手工产品主档货号原样保存，匹配时同时比较原值和生命周期截断值。
4. 优先匹配 SKC 货号，SKC 无匹配时匹配 SKU 货号。
5. 多个 SPU 命中时保留多 SPU 信息，不覆盖产品管理手工 SPU。
6. 没有命中时返回“未匹配”。

产品管理主表隐藏“生命周期关联”和“SKC / SKU绑定”两列，数据继续作为内部关联使用。详情面板按 `SPU → SKC → SKU` 展示当前产品匹配分支，包括：

- 生命周期 SPU 和匹配状态；
- SKC/SKU 平台 ID、完整货号和截断展示货号；
- SKC 颜色/款式属性；
- SKU 尺码/规格属性；
- 各层级最低供应价（商品列表核价价）；
- 各层级限流价格（日常调价/活动目标价候选的最小值），无值显示 `-`。

SPU 限流定价和人工处理：

- SPU 限流价格取该 SPU 下全部 SKC 自身限流价和下属 SKU 限流价的有效最小值。
- 以 SPU 最低限流价格作为独立基准，计算限流利润率、限流建议折扣、限流最终折扣、限流活动价、限流流量价和限流 ROAS。
- 限流派生字段只在 SPU 层显示；SKC/SKU 继续展示原始属性、供应价和限流价格，不增加派生定价字段。
- “限流 SKC”按钮展示该 SPU 下所有存在有效限流价格的 SKC 和下属 SKU，供 Temu 运营人员人工判断，不自动执行操作。

列表常态显示设置：

- 用户可选择产品管理列表常态显示列，操作列固定显示，内部 ID 不可选。
- 偏好按用户保存到 `user_settings`，同一用户在所有店铺共用一套设置。

产品管理搜索：

- SPU、SKC、SKU 为精确搜索；
- 货号为模糊搜索，同时覆盖主档原货号、主档截断值、生命周期完整货号和截断值；
- 每个字段支持空格分隔多个关键词，同字段内任意命中；
- 不同字段之间同时满足；
- 所有搜索继续遵守当前店铺和“我的数据 / 全店数据”作用域。

## 7. 数据质量要求

- 店铺档案页必须提供手动生命周期同步入口，运行中的同店铺任务不可重复提交。
- 请求分页始终保留 `[12]`。
- 原始响应按同步批次和页码归档，完整 SKC/SKU 平台货号不得丢失。
- 空价格使用空值，不以 `0` 伪造。
- 最低供应价和限流价格严格分离，限流价格不得从供应价兜底。
- 自动建档无法解析货值或序列号时保持空值，不使用最低供应价或 `0` 伪造。
- 自动同步不得覆盖手工主档；本轮不修改历史产品主档货号。
- 每个 SKU 必须关联一个 SKC，每个 SKC 必须关联一个 SPU。
- 店铺 ID 参与所有查询和唯一性约束。
- 结构未知字段保留 JSON，便于后续解析升级。
- 流量与生命周期均只保留每个 SPU 的主图 URL，不建立生命周期图片明细表。
- 已有本地图片优先；流量 URL 优先于生命周期 URL；相同 SPU 和 URL 不重复下载。
- 产品管理页面明确区分未匹配、单 SPU 和多 SPU。
- 产品管理搜索必须使用参数绑定，并保持店铺及作用域隔离。
