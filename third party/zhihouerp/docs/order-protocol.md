# 智猴 ERP 订单协议请求方案

## 1. 结论

智猴 ERP 订单数据可以通过 HTTP 协议直接获取，无需持续操作浏览器页面。

已完成实际验证：使用标准 HTTP 请求绕过页面组件，订单接口正常返回 JSON 数据。

验证结果：

- HTTP 状态码：`200`
- 业务状态码：`200`
- 响应格式：JSON
- 请求体：未加密 JSON
- 动态签名：未发现
- Cookie 依赖：未发现
- 核心鉴权：`x-access-token`

推荐采用以下方式：

> 协议请求负责订单采集，浏览器仅负责登录及令牌续期。

## 2. 接口信息

### 2.1 基本信息

| 项目         | 内容                                                 |
| ------------ | ---------------------------------------------------- |
| 接口用途     | 分页查询订单                                         |
| 请求地址     | `https://api-cn.zhfulfill.com/erp/dealer/order/page` |
| 请求方法     | `POST`                                               |
| Content-Type | `application/json;charset=UTF-8`                     |
| 鉴权请求头   | `x-access-token`                                     |

### 2.2 必要请求头

```http
Content-Type: application/json;charset=UTF-8
Accept: application/json, text/plain, */*
x-access-token: <有效访问令牌>
```

访问令牌属于敏感数据，不得写入代码仓库或日志文件。程序应通过环境变量、凭据存储或运行时配置注入。

## 3. 请求参数

新订单查询的已验证请求体如下：

```json
{
  "trackingStatus": "ALL",
  "timeField": "CREATE_TIME",
  "customCarrierIds": [],
  "packageStatus": [],
  "otherLogisticsIds": [],
  "orderDataType": "",
  "logisticsChannelIds": [],
  "storeIds": [],
  "virtualShipment": "",
  "isBind": "",
  "isY2": "",
  "countryCodes": [],
  "orderStatus": "PENDING",
  "pageNo": 1,
  "pageSize": 50
}
```

### 3.1 已确认参数

| 参数                  | 说明                                                     | 示例          |
| --------------------- | -------------------------------------------------------- | ------------- |
| `orderStatus`         | 订单状态；`PENDING` 表示当前页面查询的新订单或待处理订单 | `PENDING`     |
| `pageNo`              | 页码，从 `1` 开始                                        | `1`           |
| `pageSize`            | 每页数量                                                 | `50`          |
| `trackingStatus`      | 物流跟踪状态                                             | `ALL`         |
| `timeField`           | 时间筛选字段                                             | `CREATE_TIME` |
| `storeIds`            | 店铺 ID 列表；空数组表示不限                             | `[]`          |
| `countryCodes`        | 国家代码列表；空数组表示不限                             | `[]`          |
| `logisticsChannelIds` | 物流渠道 ID 列表；空数组表示不限                         | `[]`          |

其余空数组或空字符串参数表示不启用对应筛选条件。若后续需要精确筛选，应通过页面操作重新监听并对比参数变化。

## 4. 响应结构

接口返回结构如下：

```json
{
  "code": 200,
  "data": {
    "totalCount": 110,
    "pageNo": 1,
    "pageSize": 50,
    "data": []
  }
}
```

### 4.1 分页字段

| 字段              | 说明               |
| ----------------- | ------------------ |
| `code`            | 业务状态码         |
| `data.totalCount` | 符合条件的订单总数 |
| `data.pageNo`     | 当前页码           |
| `data.pageSize`   | 当前分页大小       |
| `data.data`       | 当前页订单数组     |

### 4.2 已确认订单字段类别

订单对象已确认包含以下数据：

- 订单 ID、订单编号、订单来源和订单状态
- 创建时间、更新时间、提交时间和发货时间
- 店铺 ID、店铺名称和店铺类型
- SKU、商品明细、商品数量和包裹数据
- 收件人、国家代码和完整地址
- 总价、结算价、折扣、运费和币种
- 物流商、物流渠道、运单号和面单地址
- 采购、生产、配货、包裹和发货状态
- 客户备注、经销商备注和供应商备注

## 5. 协议调用流程

### 5.1 推荐流程

1. 获取有效的 `x-access-token`。
2. 构造订单查询 JSON 请求体。
3. 调用订单分页接口。
4. 检查 HTTP 状态码和业务状态码。
5. 读取 `totalCount`、`pageNo` 和 `pageSize`。
6. 持续增加 `pageNo`，直到取得全部订单。
7. 对订单编号或订单 ID 去重。
8. 令牌失效时暂停请求并执行登录续期。

### 5.2 分页终止条件

可使用以下任一方式判断结束：

```text
pageNo * pageSize >= totalCount
```

或：

```text
当前页返回数量 < pageSize
```

建议同时使用两种判断，避免服务端分页数据异常导致无限循环。

## 6. 鉴权与登录

### 6.1 令牌使用

订单接口通过以下请求头鉴权：

```http
x-access-token: <有效访问令牌>
```

当前验证未发现以下依赖：

- Cookie 会话绑定
- 请求时间戳签名
- 请求体摘要签名
- 参数加密
- 浏览器设备指纹校验

### 6.2 登录限制

登录过程存在验证码参数。当前尚未验证以下内容：

- 验证码是否每次登录都必须提交
- 验证码是否可通过协议自动识别或绕过
- 访问令牌有效期
- 是否存在刷新令牌
- 同一令牌能否在不同设备或 IP 上使用

因此，首版程序应采用混合模式：

1. 浏览器完成登录。
2. 程序从已登录会话读取访问令牌。
3. 后续订单查询全部使用 HTTP 协议。
4. 令牌失效后重新启动浏览器登录并更新令牌。

## 7. 实现要求

### 7.1 安全要求

- 不得在代码中硬编码账号、密码或访问令牌。
- 不得将完整请求头输出到普通日志。
- 日志中的令牌最多保留首尾各 4 位。
- 登录失败日志不得包含密码和验证码答案。
- 配置文件应加入版本控制忽略列表。

### 7.2 稳定性要求

- 设置连接超时和响应超时。
- 对网络错误和 `5xx` 错误执行有限次数重试。
- 对 `401`、`403` 或业务鉴权失败禁止盲目重试。
- 分页请求之间设置合理间隔。
- 保存已处理订单 ID，避免重复处理。
- 对接口字段缺失使用兼容性解析，不直接导致整个任务失败。

### 7.3 建议模块

后续实现时应按功能拆分：

```text
src/
  auth/
    token-provider
    browser-login
  client/
    erp-http-client
  orders/
    order-api
    order-paginator
    order-model
  config/
    settings
  storage/
    order-checkpoint
```
